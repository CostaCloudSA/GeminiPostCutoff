## 🚫 Critical Anti-Patterns & Architecture Traps

> [!CAUTION]
> **Anti-Pattern 1: Single-Region GPU Quota Bottleneck [03.26]**
> Binding high-throughput LLM endpoints to a single GKE cluster in one region guarantees failure when regional GPU spot instances preempt or capacity pools exhaust during peak spikes.
> - **Solution**: Deploy **Multi-Cluster GKE Inference Gateway**, which actively load-balances requests across regional GKE clusters based on real-time GPU queue depth.
> *Cites: [Introducing multi-cluster GKE Inference Gateway: Scale AI workloads around the world](./references/articles.md)*

> [!WARNING]
> **Anti-Pattern 2: Serving LLMs without PagedAttention & Continuous Batching [12.25]**
> Deploying standard naive Flask/Triton containers without PagedAttention causes severe KV-cache memory fragmentation, caps concurrency at low single digits, and quadruples Time-To-First-Token (TTFT).
> - **Solution**: Standardize on **vLLM** with chunked prefill, tensor parallelism, and local NVMe SSD caching for Hugging Face model weights.
> *Cites: [ADK Agents on GKE with Self-Hosted LLMs & vLLM](./references/articles.md)*

> [!CAUTION]
> **Anti-Pattern 3: Untrusted Agent Code Execution on Host Worker Nodes [07.26, 05.26]**
> Letting autonomous coding agents execute generated scripts directly in standard pods risks host namespace breakout, credential theft from metadata servers, and node instability.
> - **Solution**: Run execution environments in **GKE Agent Sandbox**, which leverages Google gVisor kernel virtualization to isolate untrusted code while slashing idle instance costs by 75%.
> *Cites: [Reduce your agent's costs by 75% with GKE Agent Sandbox](./references/articles.md) and [Agent Sandbox on GKE is now available for everyone](./references/articles.md)*

> [!WARNING]
> **Anti-Pattern 4: Dynamic Model Weight Pulls from Public Hugging Face at Pod Startup [03.26]**
> Allowing pods to pull multi-gigabyte safetensors files directly from Hugging Face during pod startup saturates egress NAT gateways, introduces rate-limit failures, and blows cold-start times past 15 minutes.
> - **Solution**: Cache weights inside Google Cloud Storage (GCS) buckets mounted via **GCS FUSE driver** with local NVMe SSD cache, or pre-bake weights into Artifact Registry OCI container images.
> *Cites: [How to Deploy LLM Inference on GKE — The Parts Tutorials Skip](./references/articles.md) and [Inference on GKE Private Clusters](./references/articles.md)*

> [!CAUTION]
> **Anti-Pattern 5: Naive Round-Robin Load Balancing on LLM Endpoints [02.26]**
> Routing LLM inference requests across worker pods using standard round-robin or least-connections ignores KV-cache affinity, resulting in redundant prefill computation across replicas and inflating latency by up to 35%.
> - **Solution**: Deploy **GKE Inference Gateway with Utilization-Based Balancing (UBB)** and prefix-aware KV-cache routing to direct repeated prompts to warm model replicas.
> *Cites: [How we cut Vertex AI latency by 35% with GKE Inference Gateway](./references/articles.md)*

## 🛠️ Production Blueprints

### Blueprint 1: High-Performance vLLM Deployment on NVIDIA L4 with Local NVMe Cache [12.25]
Serve Gemma 2/4 with vLLM using mounted GCS weights and GPU memory optimization:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-gemma-serving
  namespace: ai-inference
spec:
  replicas: 2
  selector:
    matchLabels:
      app: vllm-gemma
  template:
    metadata:
      labels:
        app: vllm-gemma
    spec:
      nodeSelector:
        cloud.google.com/gke-gpu: "nvidia-l4"
      containers:
      - name: vllm-server
        image: vllm/vllm-openai:latest
        args:
        - "--model=/models/gemma-4-12b-it"
        - "--tensor-parallel-size=1"
        - "--max-model-len=8192"
        - "--gpu-memory-utilization=0.90"
        - "--enforce-eager"
        ports:
        - containerPort: 8000
        resources:
          limits:
            nvidia.com/gpu: 1
            memory: "32Gi"
            cpu: "8"
          requests:
            nvidia.com/gpu: 1
            memory: "32Gi"
            cpu: "8"
        volumeMounts:
        - name: model-weights
          mountPath: /models
          readOnly: true
      volumes:
      - name: model-weights
        csi:
          driver: gcsfuse.csi.storage.gke.io
          readOnly: true
          volumeAttributes:
            bucketName: my-org-curated-models
            mountOptions: "implicit-dirs,file-cache:max-size-mb:200000"
```
*Cites: [ADK Agents on GKE with Self-Hosted LLMs & vLLM](./references/articles.md)*

### Blueprint 2: GKE Inference Gateway with KV-Cache-Aware Routing [02.26, 10.25]
Route prompt prefixes to the exact inference pod holding warm KV-caches to reduce TTFT by 35%:
```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: kv-aware-inference-router
  namespace: ai-inference
spec:
  parentRefs:
  - name: gke-inference-gateway
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /v1/chat/completions
    backendRefs:
    - name: vllm-serving-service
      port: 8000
      filters:
      - type: ExtensionRef
        extensionRef:
          group: networking.gke.io
          kind: InferenceRoutingPolicy
          name: kv-cache-affinity
```

### Blueprint 4: Distributed Ray Cluster on Cloud TPU v5e via KubeRay [11.25, 05.26]

```yaml
apiVersion: ray.io/v1
kind: RayCluster
metadata:
  name: ray-tpu-cluster
  namespace: ai-inference
spec:
  headGroupSpec:
    rayStartParams:
      dashboard-host: '0.0.0.0'
    template:
      spec:

        - name: ray-worker
          image: rayproject/ray-ml:latest

            limits:
              google.com/tpu: 4
```

### Blueprint 5: Distributed Batch AI Queueing with Kueue [09.25]
Manage fair sharing and priority batch scheduling for GPU/TPU training and inference jobs:
```yaml
apiVersion: kueue.x-k8s.io/v1beta1
kind: ResourceFlavor
metadata:
  name: "nvidia-l4-flavor"
spec:
  nodeLabels:
    cloud.google.com/gke-accelerator: nvidia-l4
---
apiVersion: kueue.x-k8s.io/v1beta1
kind: ClusterQueue
metadata:
  name: "cluster-ai-queue"
spec:
  namespaceSelector: {} # Match all namespaces
  resourceGroups:
  - coveredResources: ["cpu", "memory", "nvidia.com/gpu"]
    flavors:
    - name: "nvidia-l4-flavor"
      resources:
      - name: "nvidia.com/gpu"
        nominalQuota: 16
---
apiVersion: kueue.x-k8s.io/v1beta1
kind: LocalQueue
metadata:
  name: "inference-eval-queue"
  namespace: ai-inference
spec:
  clusterQueue: "cluster-ai-queue"
```
